# Dekamoji 開発計画書（ドラフト）

最終更新: 2026-03-15  
原本: `docs/plan.md`（要件整理）

## 目的（要件整理）

`docs/plan.md` の要件整理を、実装に進めるための段階的な開発計画（フェーズ分割・完了条件・検証方法つき）へ変換する。

## 背景（要件整理）

入力した Unicode 文字列を、PC/スマートフォン/タブレットで「画面いっぱいに大きく」表示し、紙などへ手書きで転記する支援をする。ログイン不要・インストール不要の軽量なフロントエンド専用 Web アプリとして、静的配信（CDN 前提）で運用コストと障害点を最小化する。

## 対象範囲（要件整理）

初期スコープ（`docs/plan.md` より）:

- 文字入力
- 全画面表示（Fullscreen API 対応、非対応環境でも高占有表示）
- レスポンシブ対応（PC/SP/tablet、縦横回転）
- Unicode 文字列の表示（入力文字列を制限しない）
- 文字色変更
- ライトモード / ダークモード切替
- フォント変更（初期はシステムフォント中心）
- 入力履歴の保持（直近10件程度、LocalStorage）
- PDF 出力（初期は印刷 CSS + ブラウザの PDF 保存を優先）

## 非対象範囲（要件整理）

`docs/plan.md` のスコープ外:

- ユーザーアカウント機能、ログイン/会員登録
- サーバー保存、バックエンド API
- 共有 URL 生成、複数人同時編集
- OCR/文字認識、手書き入力、管理画面

## 技術方針（要件整理）

`docs/plan.md` の決定事項（抜粋）:

- アーキテクチャ: 静的配信のフロントエンド専用 SPA
- ビルド: Vite
- UI: Preact
- 言語: TypeScript
- 状態管理: Signals
- スタイル: 素の CSS または CSS Modules
- ローカル開発: Docker + npm scripts
- 保存: LocalStorage
- PDF: 印刷 CSS + ブラウザの PDF 保存を優先
- デプロイ先候補: S3 + CloudFront / Amplify Hosting / GitHub Pages（第一候補は S3+CloudFront または Amplify）

## 計画上の判断（本計画書の暫定）

要件整理に明示がない点は、実装に進めるために以下を暫定方針として置く（必要なら未確定事項で再決定する）。

- 変更戦略: 一括導入（新規アプリとして段階的に機能を積み上げる）。機能フラグは当面不要。
- 入力反映: 「入力しながら即時反映」を基本とし、モバイルでの誤操作が問題なら「表示ボタン反映」へ切替可能にする。
- テキストの改行: まずは単一行中心（折返し/縮小を優先）。複数行対応は未確定事項として扱う。
- 長文時挙動: 「収まり優先で縮小」+ しきい値超過時に警告表示（警告の有無は未確定事項）。
- フォント選択肢: 初期は OS 既定のシステムフォント系を数種（ゴシック/明朝/等幅/UD 系）に限定する。Web フォントは導入しない。
- ルーティング: 画面は「入力/設定」と「表示（全画面）」の 2 画面を基本とする（SPA 内で状態遷移）。
- セキュリティ: 入力文字列は HTML 解釈せずテキストとして描画（`docs/plan.md` の XSS 方針）。

## 検証方法（計画）

本計画書では、具体コマンドは「プロジェクトで採用されている npm scripts」に合わせて確定する（未確定事項）。最低限の検証は以下を満たすこと。

- 自動検証（存在するもののみ実行）:
  - `npm run lint`（存在する場合）
  - `npm run typecheck`（存在する場合）
  - `npm test` または `npm run test`（存在する場合）
  - `npm run build`
- 手動確認:
  - PC（Chrome/Edge/Firefox）で UC-01〜04 を通す
  - iOS Safari / Android Chrome で表示、回転、キーボード表示時のレイアウト、全画面挙動を確認
  - 長文入力時の挙動（縮小/折返し/警告）を確認
  - PDF 出力の見え方を主要ブラウザで比較（Should 実施時）
- 非機能観点（軽量性）:
  - 初回表示が極端に遅くならないこと（追加ライブラリ・フォントを増やしすぎない）

## ユーザー確認事項

1. 改行を含む入力の扱い（重要度: High）
   - 背景: 要件整理で「設計時に決定」とされ、表示アルゴリズムが変わるため
   - 選択肢: `A) 単一行中心（改行は無視/置換） / B) 複数行対応（改行をそのまま表示）`
